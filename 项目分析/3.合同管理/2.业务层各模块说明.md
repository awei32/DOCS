# 合同管理业务层各模块详细说明

## 概述

合同管理业务层（`capinfo-gjj-busi-grdk-ht-busi`）围绕“合同主流程 + 担保策略 + 外部服务接口”三条主线组织：

- 合同主流程：合同新增、签字、查询、删除、变更数据落库
- 担保策略主线：按贷款担保类型切换“保证 / 抵押 / 抵押+阶段性担保”处理策略
- 外部服务主线：黄河链、担保公司、山东数据局、报表签章与模板能力

业务层包结构整体为：

- `config`
- `controller`
- `domain`
- `service`
- `validator`
- `fwjk`

***

### 4. domain 包 - 领域数据层

**作用**：承载合同域实体、DO、Mapper 与 DmService，负责持久化与数据查询编排。

#### 4.1 组织结构

- `domain/entity`：实体模型（如 `HtJk`、`HtDb`、`HtDbDydb`、`HtDbBz` 等）
- `domain/dao`：DO对象与表映射
- `domain/dao/mapper`：MyBatis Mapper 接口
- `domain/service`：领域服务接口（20个）
- `domain/service/impl`：领域服务实现（20个）

#### 4.2 典型领域链路

- `HtServiceImpl` 调用领域服务进行合同主数据落库
- 担保策略实现类调用 `HtDbBzService/HtDbDydbService` 处理不同担保数据
- 典型文件：
  - [HtDbDmServiceImpl](file:///root/capinfo/gjj/capinfo-gjj-busi-grdk/capinfo-gjj-busi-grdk-ht/capinfo-gjj-busi-grdk-ht-busi/src/main/java/cn/capinfo/gjj/busi/grdk/ht/busi/domain/service/impl/HtDbDmServiceImpl.java#L24-L99)

## 架构特点总结

### 1. 双域协同

- `busi` 负责合同核心交易能力，`fwjk` 负责外联查询与报表签章能力，边界清晰。

### 2. 策略模式落地

- 担保处理通过 `HtDbStrategyFactory + HtDbFactory` 实现按类型扩展，降低耦合。

### 3. 领域服务沉淀充分

- `domain/service` 与 `domain/service/impl` 一一对应，形成稳定的数据访问与领域操作层。

### 4. 同步 + 异步并存

- 同步 REST 接口与 Kafka 事件并行使用，支持交互型业务与后台自动生成任务。

### 5. 跨模块协同明显

- 合同流程中直接联动 `sq`、`lp` 等模块接口，体现贷款全流程编排特征。

## 典型调用流程

```text
合同新增
  -> HtController.addHt
  -> HtServiceImpl.addHt
      -> SqFeignClient 查询/回写贷款申请信息
      -> Ht*DmService 持久化合同主数据
      -> 返回合同编号与处理结果

担保信息维护
  -> HtDbInfoController.saveDbInfo/queryDbInfo
  -> HtDbFactory.getHtDbStrategyFactory(dkdblx)
  -> HtDbInfoServiceImpl / HtDyInfoServiceImpl / HtDbDyInfoServiceImpl
  -> 对应领域服务落库

自动生成合同（异步）
  -> Kafka Topic
  -> GrdkHtSub + MessageDispatcher
  -> HtHandler.handle
  -> HtService.addHt
```
