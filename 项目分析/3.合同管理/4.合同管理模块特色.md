# 合同管理模块特色

## 一、模块概述

合同管理模块（`capinfo-gjj-busi-grdk-ht`）是个人贷款业务系统的核心组成部分，负责管理贷款合同的生成、变更、查询等全生命周期管理。该模块采用微服务架构设计，通过FeignClient与其他模块进行服务间通信。

---

## 二、核心功能特色

### 2.1 合同类型多样化管理

模块支持多种合同类型的管理，满足不同贷款场景需求：

| 合同类型 | 说明 | 对应实体 |
|---------|------|---------|
| 借款合同 | 记录借款人与公积金中心的借款关系 | `HtJk` |
| 担保合同 | 记录贷款担保信息 | `HtDb` |
| 抵押担保 | 房产抵押相关合同信息 | `HtDbDydb` |
| 保证担保 | 第三方保证担保信息 | `HtDbBz` |
| 担保公司协议 | 与担保公司的合作协议 | `HtDbgs` |
| 委托银行协议 | 与受托银行的合作协议 | `HtWtyh` |

### 2.2 合同变更管理

系统支持多种合同变更类型，确保贷款期间信息变更的灵活性和可追溯性：

#### 2.2.1 支持的变更类型

1. **借款人变更** (`HtBgJkr`)
   - 支持主借款人信息变更
   - 支持共同借款人信息变更
   - 记录变更前后的完整信息对比

2. **还款账号变更** (`HtBgHkzh`)
   - 支持还款银行账户变更
   - 自动关联受托银行信息
   - 变更历史完整记录

3. **期限变更** (`HtBgQxbg`)
   - 支持贷款期限延长或缩短
   - 自动重新计算贷款期数、利率
   - 记录变更前后的期限、利率对比

4. **还款方式变更** (`HtBgDkhkfsbg`)
   - 支持等额本息、等额本金等方式切换
   - 变更后重新生成还款计划

### 2.3 策略模式实现担保类型管理

模块采用**策略模式（Strategy Pattern）**实现不同担保类型的灵活管理：

#### 2.3.1 设计架构

```
HtDbStrategyFactory (接口)
    ├── HtDyInfoServiceImpl    - 抵押担保策略实现
    └── HtDbInfoServiceImpl    - 保证担保策略实现
```

#### 2.3.2 核心代码实现

- **策略接口定义**：`HtDbStrategyFactory`
  - `getHtDbsqResDTO()` - 查询担保信息
  - `saveHtDbsqResDTO()` - 保存担保信息
  - `deleteHtDbsqResDTO()` - 删除担保信息

- **策略工厂**：`HtDbFactory`
  - 使用Map缓存策略实例
  - 根据担保类型代码(`dkdblx`)动态获取对应策略
  - 实现策略的注册与获取

#### 2.3.3 优势

1. **开闭原则**：新增担保类型只需添加新的策略实现，无需修改现有代码
2. **单一职责**：每种担保类型的业务逻辑独立封装
3. **可扩展性**：支持灵活扩展新的担保类型

### 2.4 合同清单管理

`HtQd`（合同清单）实体实现合同的全生命周期跟踪：

#### 2.4.1 功能特点

- **合同类型标识**：记录合同/变更的具体类型
- **生效日期管理**：记录合同的生效时间
- **审批状态跟踪**：记录合同当前的审批状态
- **渠道信息记录**：记录合同办理的渠道来源

#### 2.4.2 清单类型覆盖

- 借款合同清单
- 担保合同清单
- 各类变更合同清单（还款账号、借款人、期限、还款方式等）

### 2.5 抵押物管理特色

#### 2.5.1 抵押物类型支持

支持多种抵押物类型管理：

| 抵押物类型 | 代码 | 说明 |
|-----------|------|------|
| 所购住房 | 01 | 贷款购买的住房 |
| 自有他处住房 | 02 | 借款人名下的其他房产 |
| 第三人房产 | 03 | 第三方提供的房产抵押 |

#### 2.5.2 抵押状态管理

- **抵押类型**：预抵押(01) / 正式抵押(02)
- **抵押权建立日期**：记录抵押生效时间
- **抵押权解除日期**：记录抵押解除时间
- **权证号管理**：支持抵押物权证号、他项权证号、预告登记证号

#### 2.5.3 抵押人管理

- 支持多个抵押人关联同一抵押物
- 抵押人信息独立维护
- 支持抵押人变更历史记录

### 2.6 合同编号生成策略

系统支持灵活的合同编号生成方式：

```java
// 从系统参数获取生成方式
CsXtcsDTO jkhtbhScfsXtcsDTO = ParamUtil.parm(zxbh, "SysCode", "JKHTBH", "SCFS", new Date());
String jkhtbhScfs = jkhtbhScfsXtcsDTO.getCsValue();

// 支持多种生成策略
if ("2".equals(jkhtbhScfs)) {
    jkhtbh = sqbh;  // 使用申请编号作为合同编号
}
```

### 2.7 业务受理编号管理

- 使用流水号工具(`LshTools`)生成唯一业务受理编号
- 每笔合同/变更业务都有独立的业务受理编号
- 支持按中心、业务类型生成不同前缀的流水号

## 三、技术实现特色

### 3.1 分层架构设计

```
controller/     - 控制层：处理HTTP请求，参数校验
service/        - 业务层：处理业务逻辑
  ├── impl/     - 业务实现
  └── domain/   - 领域服务
    ├── service/ - 领域服务实现
    ├── entity/  - 领域实体
    ├── dao/     - 数据访问对象
    └── factory/ - 工厂类
```

### 3.2 数据一致性保障

- **事务管理**：使用`@Transactional`注解确保业务操作原子性
- **乐观锁机制**：使用`revision`字段实现并发控制
- **异常处理**：统一异常处理机制，确保数据完整性

### 3.3 FeignClient服务调用

模块通过FeignClient与其他微服务进行通信：

| 调用服务 | 用途 |
|---------|------|
| `SqFeignClient` | 获取贷款申请信息、同步合同信息 |
| `JzglFeignClient` | 查询公积金账户缴存信息 |

### 3.4 数据校验机制

- 使用`@Check`注解进行参数校验
- 自定义校验器实现复杂业务规则校验
- 支持担保信息重复性校验、抵押权证号唯一性校验

## 四、关键业务场景

### 4.1 合同生成流程

1. 接收贷款申请编号
2. 校验申请状态（必须为审批通过）
3. 生成借款合同编号
4. 生成业务受理编号
5. 保存担保合同信息
6. 同步更新贷款申请信息
7. 记录合同清单

### 4.2 合同签字流程

1. 接收合同类型和申请编号
2. 根据合同类型更新对应合同状态
3. 同步更新贷款申请状态
4. 记录签字时间

### 4.3 合同变更流程

1. 接收变更申请
2. 校验变更条件
3. 生成业务受理编号
4. 保存变更信息
5. 记录合同清单
6. 触发相关后续业务（如重新生成还款计划）

## 六、扩展性设计

### 6.1 新增担保类型

如需新增担保类型，只需：

1. 创建新的策略实现类，实现`HtDbStrategyFactory`接口
2. 在`afterPropertiesSet()`方法中注册到工厂
3. 无需修改现有业务代码

### 6.2 新增合同变更类型

1. 创建变更实体类继承`BaseEntity`
2. 创建对应的Service接口和实现
3. 在`HtController`中添加接口方法
4. 在`HtService`中实现变更逻辑

---

## 七、总结

合同管理模块通过**策略模式**实现了担保类型的灵活管理，通过**分层架构**确保了代码的可维护性，通过**完善的变更管理**满足了业务灵活性需求。模块设计充分考虑了扩展性，能够适应未来业务发展的需要。
