# 贷款申请业务层各模块详细说明

## 概述
贷款申请业务层（BUSI层）采用领域驱动设计（DDD）思想，通过清晰的包结构组织业务逻辑，实现高内聚、低耦合的架构设计。各模块职责明确，便于维护和扩展。

## 各模块详细说明

### 1. config 包 - 配置管理
**作用**：Web应用配置类，继承基础配置，提供模块特定的配置能力。
- **主要类**：[SqWebConfiguration](file:///root/capinfo/gjj/capinfo-gjj-busi-grdk/capinfo-gjj-busi-grdk-sq/capinfo-gjj-busi-grdk-sq-busi/src/main/java/cn/capinfo/gjj/busi/grdk/sq/busi/config/SqWebConfiguration.java)
- **核心基类**：`cn.capinfo.gjj.core.common.config.BaseConfig`
- **BaseConfig详细功能**：
  
  **🔧 JSON序列化/反序列化配置**
  - **大数字精度保护**：可选将Long/BigInteger/BigDecimal转为字符串，避免JavaScript精度丢失
  - **未知字段兼容**：`FAIL_ON_UNKNOWN_PROPERTIES = false`，忽略前端传递的未知字段
  - **特殊字符支持**：启用单引号、控制字符等非标准JSON格式解析
  - **容错性增强**：提高JSON解析的健壮性
  
  **📅 日期时间格式标准化**
  - **统一输出格式**：
    - `LocalDateTime` → `"yyyy-MM-dd HH:mm:ss"`
    - `LocalDate` → `"yyyy-MM-dd"`  
    - `LocalTime` → `"HH:mm:ss"`
  - **时区统一**：`Asia/Shanghai`（中国标准时间）
  - **区域设置**：`Locale.CHINA`（中文格式习惯）
  
  **🔄 参数类型转换**
  - **URL参数绑定**：支持`@RequestParam("date") LocalDateTime date`直接绑定
  - **Converter注册**：
    - `String2DateConverter` - 字符串转Date
    - `String2LocalDateTimeConverter` - 字符串转LocalDateTime  
    - `String2LocalDateConverter` - 字符串转LocalDate
    - `String2LocalTimeConverter` - 字符串转LocalTime
  
  **🎯 枚举类型处理**
  - **灵活反序列化**：通过`EnumDeserializer.INSTANCE`支持code字段反序列化
  - **标准化处理**：统一枚举的序列化/反序列化行为
  
  **⚙️ 技术实现特点**
  - **@Primary ObjectMapper**：确保使用统一的JSON处理器
  - **@ConditionalOnMissingBean**：避免配置冲突
  - **抽象类设计**：便于各模块继承和扩展
  - **集中式管理**：所有业务模块共享相同的基础配置

- **特点**：
  - 继承 `BaseConfig` 基础配置类，获得统一的Web配置能力
  - 使用 `@Configuration` 注解标识为Spring配置类
  - 可扩展模块特定的Bean定义和配置
  - 遵循DRY原则，避免重复配置

### 2. context 包 - 上下文管理
**作用**：线程上下文管理工具，用于在无登录用户场景下透传机构信息等上下文数据。
- **主要类**：[ChannelContextHolder](file:///root/capinfo/gjj/capinfo-gjj-busi-grdk/capinfo-gjj-busi-grdk-sq/capinfo-gjj-busi-grdk-sq-busi/src/main/java/cn/capinfo/gjj/busi/grdk/sq/busi/context/ChannelContextHolder.java)
- **核心功能**：
  - 使用 `ThreadLocal` 存储渠道调用上下文信息
  - 支持经办机构编号、名称，操作员机构编号、名称，受理人等信息透传
  - 提供 `set()`、`get()`、`clear()` 方法管理上下文生命周期

**详细分析**：

**🔧 解决的核心问题**
- **渠道调用身份识别**：外部渠道（如爱山东APP）调用时无传统登录用户会话，无法获取操作员信息
- **业务数据完整性**：贷款申请等业务需要记录受理人、操作机构等关键信息
- **线程安全上下文传递**：确保多线程环境下上下文信息的安全隔离
- **跨服务调用一致性**：在整个请求处理链路中保持上下文信息一致

**⚙️ 技术实现细节**
- **数据结构**：`ChannelOrgInfo` 包含完整的机构和人员信息
  - `jbjgbh/jbjgmc`：经办机构编号/名称
  - `czyjgbh/czyjgmc`：操作员机构编号/名称  
  - `slr`：受理人/操作员名称
- **线程安全**：使用 `ThreadLocal<ChannelOrgInfo>` 确保每个线程独立的上下文副本
- **生命周期管理**：
  - `set()`：请求入口处设置上下文
  - `get()`：业务逻辑中读取上下文
  - `clear()`：请求结束时清理，防止内存泄漏

**🔄 实际应用场景**
- **渠道API调用**：`ChannelAdapterController` → `ChannelSqService` 设置上下文
- **业务数据填充**：`SqService`、`SqTransactionService` 读取上下文填充受理人信息
- **调用链示例**：
  ```java
  // 设置上下文（ChannelSqServiceImpl）
  ChannelOrgInfo orgInfo = new ChannelOrgInfo();
  orgInfo.setJbjgbh(grzh.getGljgbh());
  orgInfo.setSlr(grzh.getXingming());
  ChannelContextHolder.set(orgInfo);
  
  // 使用上下文（SqServiceImpl）
  if (ChannelContextHolder.get() != null) {
      ChannelOrgInfo orgInfo = ChannelContextHolder.get();
      sqDk.setSlr(orgInfo.getSlr());
      sqDk.setCzyjgbh(orgInfo.getCzyjgbh());
  }
  
  // 清理上下文（ChannelSqServiceImpl）
  ChannelContextHolder.clear();
  ```

**🎯 架构价值**
- **解耦业务逻辑**：业务服务无需关心上下文来源，只需使用统一接口
- **支持多渠道集成**：不同外部渠道都可以通过相同机制传递上下文
- **保证数据审计**：所有渠道创建的业务数据都包含完整的操作溯源信息
- **符合企业级规范**：满足金融业务对数据完整性和可追溯性的要求

- **应用场景**：
  - 渠道接口调用时传递机构信息
  - 无用户登录状态下的业务处理
  - 跨服务调用时的上下文保持

### 4. domain 包 - 领域模型层
**作用**：领域驱动设计的核心包，包含实体、数据访问对象、领域服务、工厂和事件等DDD元素。

#### 4.1 entity 包（16个实体类）
**作用**：数据库实体映射类，对应数据库表结构。
- **主要实体**：SqDk（贷款）、SqFw（房屋）、SqGtjkr（共同借款人）、SqYddkjczm（异地缴存证明）等
- **特点**：
  - 使用JPA注解或MyBatis注解映射数据库字段
  - 包含业务属性和基本的getter/setter方法
  - 实现Serializable接口支持序列化

#### 4.2 dao 包（16个DAO接口）
**作用**：数据访问对象接口，定义数据库操作方法。
- **主要接口**：SqDkDOMapper、SqFwDOMapper、SqGtjkrDOMapper等
- **特点**：

#### 4.3 service 包（16个DmService）

## 架构特点总结

### 1. 分层架构清晰
- **控制器层**：HTTP请求处理
- **应用服务层**：业务流程协调
- **领域模型层**：核心业务逻辑
- **基础设施层**：配置、上下文、工具等支撑功能

### 2. 设计模式应用
- **适配器模式**：处理外部系统数据格式差异
- **工厂模式**：复杂对象创建
- **观察者模式**：领域事件机制
- **策略模式**：多环境配置切换

### 3. 企业级特性支持
- **事务管理**：通过@Service注解和@Transactional支持
- **分布式ID**：集成TinyID分布式ID生成器
- **操作日志**：通过@OptLog注解记录操作日志
- **参数校验**：集成Hibernate Validator和自定义验证器
- **消息队列**：Kafka消息发布和订阅
- **多数据库支持**：通过Maven Profile支持MySQL/PostgreSQL/达梦/Kingbase

### 4. 可维护性和可扩展性
- **接口隔离**：服务层接口+实现分离
- **高内聚**：每个包职责单一，功能集中
- **低耦合**：通过依赖注入和接口编程降低耦合度
- **可测试性**：各层可独立进行单元测试和集成测试
