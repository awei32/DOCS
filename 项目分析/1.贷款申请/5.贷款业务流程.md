# 贷款业务流程

## 1. 文档范围

本文基于 `capinfo-gjj-busi-grdk-sq` 申请模块源码，说明贷款申请从“资料录入”到“审批回写、放款回写”的核心业务流程，覆盖柜面办理和渠道办理两条主线。

---

## 2. 核心业务主线

贷款申请模块围绕一个业务主键 `sqbh`（申请编号）组织三要素数据：

- 借款人信息（含主借款人、共同借款人）
- 房屋信息（含共有权人）
- 贷款信息（金额、期限、利率、还款方式、审批状态等）

主流程可概括为：

1. 申请编号生成
2. 借款人录入与校验
3. 房屋录入与校验
4. 贷款暂存或提交
5. 工作流审批
6. 审批结果回写
7. 放款结果回写

---

## 3. 状态流转

审批状态使用 `SpztDksqEnum`，核心状态如下：

| 状态码 | 状态名称 |
| --- | --- |
| 10 | 申请 |
| 15 | 审批退回 |
| 20 | 审批中 |
| 60 | 审批通过 |
| 65 | 合同生成 |
| 66 | 合同签字 |
| 68 | 放款审核中 |
| 70 | 放款批次生成 |
| 80 | 放款成功 |

业务上大量“可编辑”判断都依赖该状态：只有 `10/15` 可以继续修改申请资料，进入 `20` 后即视为审批中并限制修改。

## 3.1 涉及数据库表

贷款申请流程在申请模块（sq）内主要落以下表：

| 表名 | 作用 | 主要环节 |

说明：

- 主流程最核心的“四张业务表”为：`grdk_sq_dk`、`grdk_sq_gtjkr`、`grdk_sq_fw`、`grdk_sq_fw_gyqr`。

- 历史表用于变更留痕与审计，不作为主流程实时查询主表。

## 4. 柜面申请流程（核心）

### 4.1 步骤1：生成申请编号

- 接口：`POST /api/v1/sq/getSqbh`
- 处理：`SqServiceImpl.getSqbh`
- 规则：
  - 生成 `sqbh`（机构编码 + 日期 + 序号）
  - 生成 `ywslbh`（业务受理编号）

该步骤为后续借款人、房屋、贷款三要素提供统一关联键。

涉及表与字段变更：

- 本步骤不落库，仅返回编号结果。
- 返回字段：`sqbh`、`ywslbh`。

### 4.2 步骤2：录入借款人信息

- 接口：`POST /api/v1/sq/addGtjkr`
- 处理：`SqServiceImpl.addGtjkr`
- 关键业务动作：
  1. 基础信息校验（证件、参贷关系、主借款人唯一性）
  2. 审批状态拦截（非 `10/15` 不允许修改）
  3. 贷款总览协查（BDC316）
  4. 外联结果保存
  5. 首次主借款人时自动初始化贷款主记录
  6. 同步更新贷款汇总字段（家庭收入、主借款人信息等）
  7. 同步借款人到共有权人（按产权标识）

涉及表与字段变更：

- `grdk_sq_wljg`（新增外联调用记录）：
  - `ywslbh`、`wlczlx`、`ywlxbm`、`ywlxmc`、`wljkbm`、`wljkmc`（并携带请求中的申请维度字段，如 `sqbh`）。
- `grdk_sq_dk`（首次主借款人时初始化主记录）：
  - `sqbh`、`ywslbh`、`spzt`、`qdbm`、`qdlx`、`jkrxm`、`jkrzjlx`、`jkrzjh`、`jkrgjjzh`、`jtzns`、`dhzc`、`dkdlx`、`slr`、`slsj`、`czyjgbh`、`czyjgmc`、`jbjgbh`、`jbjgmc`。
- `grdk_sq_gtjkr`（新增/修改借款人）：
  - 请求体同名字段落库，并补齐默认/派生字段：`sfch`、`sfcydkedjs`、`ydlxjcys`、`jtgx`、`xuhao`、`txnl`、`dwzh`。
- `grdk_sq_dk`（借款人录入后同步汇总更新）：
  - `dkdlx`、`jtzns`、`dhzc`、`jtysr`、`jkrzjh`、`jkrxm`、`jkrzjlx`。
- `grdk_sq_fw_gyqr`（借款人同步共有权人时更新）：
  - `qlrlx`、`qllx`、`qlrmc`、`qlrzjlx`、`qlrzjhm`、`sjhm`、`xingbie`、`nianling`、`gzdw`、`dwxz`、`dwdh`、`lxdz`、`gyqrlx`、`yjkrgx`（关联字段 `sqbh`、`fwjyid`、`fwid`）。

### 4.3 步骤3：录入房屋信息

- 接口：`POST /api/v1/sq/addFw`
- 处理：`SqServiceImpl.addFw`
- 关键业务动作：
  1. 审批状态拦截（非 `10/15` 不允许修改）
  2. 归一化房屋请求数据
  3. 新事务保存房屋主数据
  4. 按开关执行房屋规则校验（规则引擎）
  5. 校验并重建共有权人明细
  6. 若有网签合同编号，异步处理电子合同下载与归档

涉及表与字段变更：

- `grdk_sq_fw`（新增/修改房屋主数据）：
  - 按 `SqFwReqDTO` 同名字段落库，核心字段包括：`sqbh`、`ywslbh`、`fwzl`、`fwjzmj`、`fwtnmj`、`fwnl`、`fwlx`、`gflx`、`fwzj`、`gfsfk`、`xmId`、`fwId`、`xzqh1~xzqh4`、`wqhtbh` 等。
- `grdk_sq_fw_gyqr`（重建共有权人明细）：
  - 先按 `sqbh` 删除旧记录，再批量新增。
  - 新增字段为请求体同名字段 + 关联字段：`fwId`、`fwjyid`、`fwid`、`sqbh`。

### 4.4 步骤4：暂存贷款信息

- 接口：`POST /api/v1/sq/tempSaveDk`
- 处理：`SqServiceImpl.tempSaveDk`
- 作用：只落库，不启动工作流，便于分步录入后续继续编辑。

涉及表与字段变更：

- `grdk_sq_dk`（保存/更新贷款主数据）：
  - 请求体同名字段落库，并在保存前补齐派生字段：`htdkje`、`sydked`、`dkqs`、`yhbh`、`dyghbz`、`jkhtll`、`jtzns`、`czyjgbh`、`czyjgmc`、`sfsbzfdk`、`lllx`。
  - 本步骤不变更流程字段，不写 `wkid`，审批状态保持当前值（通常为 `10/15`）。

### 4.5 步骤5：提交受理（关键提交点）

- 接口：`POST /api/v1/sq/addDk`
- 主处理：`SqServiceImpl.addDk -> addSqDk -> processWorkflowAndQuery`
- 提交链路：

1. 保存贷款主数据  
   由 `SqTransactionServiceImpl.saveSqDkData` 在独立事务中完成，先保证数据入库。

2. 规则引擎串行校验  
   `SqTransactionServiceImpl.validateByRuleEngine` 按顺序执行：
   - 借款信息校验
   - 可贷金额校验
   - 可贷年限校验

3. 启动审批工作流  
   在状态为 `10/15` 时调用 `createProcess`：
   - 组装三要素完整业务数据
   - 调用审批服务创建流程实例
   - 将贷款状态更新为 `20`（审批中）
   - 回写 `wkid`（流程实例ID）

4. 异步个人事项通知  
   调用 `sendGrsxMsg` 发布个人事项消息，不阻塞主交易返回。

涉及表与字段变更：

- `grdk_sq_dk`（提交前再次保存）：
  - 与“步骤4暂存”同口径，先落完整贷款主数据。
- `grdk_sq_dk`（启动流程后状态更新）：
  - `spzt`：由 `10/15` 更新为 `20`（审批中）。
  - `wkid`：回写流程实例ID。
- 个人事项通知为异步消息发送，不在本方法内直接更新申请模块主表。

## 5. 审批回写流程

### 5.1 贷款申请审批结果回写

- 消费处理器：`SqDksqHandler`
- 事件类型：`GRDK_SQ_DKSQ_TOPIC`
- 回写逻辑：
  - 审批通过：状态置为 `60`
  - 审批拒绝：状态置为 `15`
  - 同步写入审批意见、审批人、审批时间

扩展动作：

- 若审批通过且担保类型为保证担保，则触发合同侧自动生成合同事件。

### 5.2 放款结果回写

- 消费处理器：`FkDkztEditHandler`
- 事件类型：`GRDK_SQ_FKDKZTGX_TOPIC`
- 回写逻辑：
  - 放款失败：状态回写为放款批次阶段，记录失败原因
  - 放款成功：状态置为 `80`，更新放款结果、放款日期等字段

至此形成“申请提交 -> 审批 -> 放款 -> 主数据回写”的闭环。

## 6. 渠道申请流程（外部接入）

渠道统一入口：`ChannelSqServiceImpl.processApply`，总体结构与柜面一致，但通过适配器完成渠道字段转换。

流程如下：

1. 校验是否存在待受理申请，避免重复进件
2. 调用 `getSqbh` 生成申请编号
3. 处理借款人（主借款人 + 共同借款人）
4. 处理房屋信息
5. 处理贷款信息（渠道侧默认走暂存）
6. 在 `finally` 中清理渠道上下文

渠道特性：

- 通过 `ChannelContextHolder` 注入机构与经办上下文
- 复用同一套 `sqService.addGtjkr/addFw` 核心能力
- 减少渠道与核心业务逻辑重复实现

---

## 7. 关键控制点

### 7.1 修改权限控制

借款人、房屋、贷款三类修改接口都在业务层检查审批状态，防止审批中数据被并发改写。

### 7.2 事务分层

- 主提交流程负责编排
- 落库和规则校验拆分到事务服务
- 跨服务调用放在关键步骤之后执行，降低回滚复杂度

### 7.3 规则引擎开关

通过参数开关决定是否启用规则引擎，支持生产快速切换与灰度。

### 7.4 消息异步化

审批、放款、个人事项通知采用消息驱动回写，避免主交易链路过长。

---

## 8. 端到端时序（简化）

```text
受理端/渠道
  -> getSqbh
  -> addGtjkr(主/共借)
  -> addFw(房屋+共有权人)
  -> tempSaveDk(可选)
  -> addDk(提交)
      -> saveSqDkData
      -> validateByRuleEngine
      -> createProcess(审批流)
      -> sendGrsxMsg

审批系统完成审批
  -> 发审批结果消息
  -> SqDksqHandler回写spzt(60/15)

放款系统完成放款
  -> 发放款结果消息
  -> FkDkztEditHandler回写spzt/fkzt/dkzt
```

---

## 9. 小结

贷款申请模块在流程设计上实现了三个目标：

- 数据闭环：三要素围绕 `sqbh` 一致建模
- 流程闭环：提交、审批、放款结果均能回写主数据
- 架构闭环：同步交易 + 异步事件 + 规则引擎协同，兼顾一致性与可扩展性

该流程既支撑柜面分步录入，也支撑外部渠道一体化进件，是个贷业务的统一申请中台能力。
