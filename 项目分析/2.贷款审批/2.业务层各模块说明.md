# 贷款审批业务层各模块详细说明

## 概述

贷款审批业务层（`capinfo-gjj-busi-grdk-sp-busi`）以“工作流审批中台能力”为核心，围绕以下两条主线组织：

- 审批流主线：流程创建、待办查询、审批办理、流程图、统计
- 代理与档案主线：审批代理管理、流程结束后的电子档案归档/作废

业务层包结构整体为：

- `config`
- `controller`
- `domain`
- `service`
- `validator`

---

## 各模块详细说明

### 1. config 包 - 配置管理

**作用**：承接审批模块Web基础配置，复用公共配置能力。

- **主要类**：[SpWebConfiguration](file:///root/capinfo/gjj/capinfo-gjj-busi-grdk/capinfo-gjj-busi-grdk-sp/capinfo-gjj-busi-grdk-sp-busi/src/main/java/cn/capinfo/gjj/busi/grdk/sp/busi/config/SpWebConfiguration.java#L11-L13)
- **继承基类**：`cn.capinfo.gjj.core.common.config.BaseConfig`

**关键价值**：

- 统一JSON序列化与反序列化行为
- 统一日期/时间格式与参数转换器
- 统一枚举转换策略
- 保持与 `sq/bg/hk/ht` 模块一致的Web行为基线

---

### 2. controller 包 - 控制器层

**作用**：对外提供审批REST接口，负责参数接收、校验、调用服务层并统一返回 `R<T>`。

- **核心控制器**：[SpController](file:///root/capinfo/gjj/capinfo-gjj-busi-grdk/capinfo-gjj-busi-grdk-sp/capinfo-gjj-busi-grdk-sp-busi/src/main/java/cn/capinfo/gjj/busi/grdk/sp/busi/controller/SpController.java#L33-L238)
- **路由前缀**：`/api/v1/sp`

**接口分组**：

- 流程能力：
  - `createProcess`（启动流程）
  - `completeTask`（节点审批）
  - `history` / `getWorkflowSpjl`（审批历史）
  - `processImage`（流程图）
- 待办能力：
  - `listDbrw` / `getDbrw`
- 代理能力：
  - `pageSpdl` / `addSpdl` / `editSpdl` / `deleteSpdl`
- 统计能力：
  - `listGrdbywtj` / `listBmdbywtj`
  - `listGrspltj` / `listBmspltj`

**特点**：

- 使用 `@Check` 做请求参数校验
- 使用 `@OptLog` 记录操作日志
- 控制层不承载复杂业务逻辑，复杂逻辑全部下沉到 `SpServiceImpl`

### 4. service 包 - 应用服务层

**作用**：审批核心业务编排层，连接控制器、工作流引擎、领域服务与档案服务。

#### 4.1 核心审批服务

- 接口：[SpService](file:///root/capinfo/gjj/capinfo-gjj-busi-grdk/capinfo-gjj-busi-grdk-sp/capinfo-gjj-busi-grdk-sp-busi/src/main/java/cn/capinfo/gjj/busi/grdk/sp/busi/service/SpService.java#L16-L129)
- 实现：[SpServiceImpl](file:///root/capinfo/gjj/capinfo-gjj-busi-grdk/capinfo-gjj-busi-grdk-sp/capinfo-gjj-busi-grdk-sp-busi/src/main/java/cn/capinfo/gjj/busi/grdk/sp/busi/service/impl/SpServiceImpl.java)

**核心职责**：

- 流程发起：`createProcess`
- 待办查询：`listDbrw/getDbrw`
- 节点审批：`completeTask`
- 统计分析：个人/部门待办、个人/部门审批量
- 代理管理：`pageSpdl/add/edit/delete`

**关键实现机制**：

- **待办拼装机制**：本人待办 + 审批代理待办合并，再按贷款审批流程类型过滤
- **流程完成后分发机制**：`completeTask` 中若流程结束，则触发 `dzdaprocess`
- **档案处理策略链**：遍历 `List<DzdaFactory>`，按 `matchDzda` 选择匹配策略并执行归档/作废

## 架构特点总结

### 1. 审批中心化

- `sp` 模块把流程发起、审批、待办、统计统一聚合，成为跨业务模块共享审批中台。

### 2. 工作流与业务解耦

- 审批动作通过 `WorkflowFeignClient` 驱动，业务层聚焦“参数组装 + 结果处理 + 业务回写”。

### 3. 代理机制完善

- 待办查询天然支持“本人 + 代理”视角，并按代理有效期控制生效。

### 4. 电子档案可扩展

- `DzdaFactory` + 多实现类形成策略链，支持按不同业务类型做归档与作废。

### 5. 领域对象精简

- 当前domain围绕审批代理、审批过程、审批外联三类核心对象建模，边界清晰。

## 典型调用流程

```text
外部业务模块（sq/bg/hk等）
  -> SpFeignClient 调用审批接口
  -> SpController
  -> SpServiceImpl
      -> WorkflowFeignClient（流程引擎）
      -> SpDlDmService（审批代理持久化/查询）
      -> DzdaFactory（流程结束后档案归档/作废）
```
